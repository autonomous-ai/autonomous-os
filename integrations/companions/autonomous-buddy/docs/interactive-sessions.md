# Interactive agent sessions

New Codex, Claude Code, and Terminal sessions created in the desktop UI start an interactive process immediately in the selected project/worktree. Buddy displays the real CLI through xterm and `node-pty`: keyboard input, terminal output, resizing, and focus belong to that exact session. Interactive sessions have no Buddy chat welcome screen or prompt composer. A single pane header contains the session title, current status, Stop/Resume control, split controls, and close button.

## Lifecycle and history

**Stop** ends the owned process while keeping the session visible. **Resume CLI** resumes the saved provider conversation; **Restart terminal** starts a new shell in the same worktree. If a previously used coding session has no known provider conversation ID, resume refuses to silently create a different conversation. A stopped terminal replays retained output, but restarting does not restore shell process state.

Tab **×**, pane **×**, and session-tab **⌘W** stop and archive the targeted session, removing it from the active sidebar without deleting retained history. The archived flag is persisted, so a closed session does not reappear in the active sidebar or restored panes after restarting Buddy. Other split sessions continue running. Closing the original session also closes its tab group; remaining sessions are still available from the sidebar. Explicit session deletion is a separate operation that deletes history. Closing the macOS workspace window keeps the application, helper, and other agents running; Quit stops the app's processes.

Existing sessions with structured conversation history keep their transcript, composer, and provider conversation ID. Empty legacy coding sessions migrate to interactive mode in a stopped state. New sessions default to `mode: interactive`; structured mode remains available through the backend API. This migration does not discard conversations. Layout restoration excludes archived sessions. Unread updates are cleared only for the focused pane while the window has focus.

## Provider and native boundaries

Interactive Codex launches its CLI with `--dangerously-bypass-approvals-and-sandbox --no-alt-screen`; resuming supplies the exact saved conversation ID. Claude Code uses `--dangerously-skip-permissions` with a generated `--session-id` for a new conversation or `--resume` for an existing one. These full-access settings follow the user's explicit execution preference and do not change global CLI settings or macOS permissions. Provider status and process liveness are separate: completion of a turn does not necessarily mean the interactive process exited.

Claude and Codex receive session-local provider hooks; Buddy does not edit global or project provider configuration. Codex hook trust and the selected project trust are supplied as process-local CLI overrides; inherited nested-session markers are removed before launch. `SessionStart` maps to ready/idle, prompt submission and ordinary tool events to running, permission requests and `AskUserQuestion` to needs-input, and `Stop` to completed. Claude additionally maps `StopFailure` to error and manual `PostCompact` to completed. Child-agent hook events are ignored. Hook conversation IDs must match the saved provider ID; an unexpected identity is rejected. `processActive` records whether the owned CLI is alive independently of its turn status, so a completed CLI can remain open and accept another turn.

`send` can route a voice/follow-up prompt into an interactive coding session only after a hook establishes ready or completed state, while its process is alive and no manual draft is pending. Working, needs-input, unverified readiness, and manual input block injection. The prompt is normalized, checked for terminal control characters, then sent as bracketed paste plus Enter to the **same PTY**; no new process or conversation is created. Paste and Enter are separate writes with a 500 ms settle window plus a host-dependent ingest estimate. That reservation remains held during the delay; stop, exit, or manual input cancels Enter and reports that the prompt may be pasted but not submitted. Buddy does not automatically retry this ambiguous delivery. A fresh Codex CLI may not create its thread or emit readiness until the first prompt is typed in its terminal, so voice input into an already-open fresh CLI cannot bypass this gate. Voice `agent.create` instead defaults to a deferred interactive session (idle, `processActive: false`); its first `send` launches the real CLI with the initial prompt as a positional argv argument, without typing into onboarding stdin. Subsequent sends use hook-verified readiness on that same PTY. Explicit `mode: structured` remains available for compatibility.

Raw terminal input remains scoped to the selected session through the finite preload API. Native computer use still belongs to the bundled Swift executor and its macOS permissions. Hook behavior depends on the installed provider version; the implementation and mock tests do not by themselves establish real-provider support.
